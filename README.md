# Keryx Node Manager

Windows-приложение (WPF, .NET 8) для управления Keryx-нодой (`keryxd.exe`) и GPU-майнером
(`keryx-miner.exe`) из одного окна — без ручной работы в PowerShell/WSL/Docker. Community-
инструмент, не официальный продукт Keryx Labs.

## Возможности

- **Обзор (Dashboard)** — запуск/остановка ноды и майнера одной кнопкой, статус в реальном
  времени, иконка в трее с цветовой индикацией состояния.
- **Видеокарты** — автоопределение GPU (`nvidia-smi`), автоназначение модели майнинга по объёму
  VRAM или ручной выбор тира на карту; полноценный разгон (сдвиг частоты ядра/памяти) и ручное
  управление кулером через NVAPI, с подтверждением перед применением и блокировкой при
  критическом перегреве.
- **Модели** — управляемая приложением загрузка (резюмируемая, с проверкой SHA-256) файлов моделей
  по тирам.
- **Нода** — автозапуск с нужными флагами (`--appdir`, `--rpclisten-json` и т.д.), список
  публичных нод (bundled + опциональный удалённый JSON + реальная TCP-проверка доступности),
  обнаружение адресов пиров через RPC собственной ноды, one-click загрузка/распаковка data dir
  (HTTP и торрент), переключение на резервную ноду на время синхронизации своей с автоматическим
  возвратом обратно.
- **Майнер** — запуск с привязкой к назначенным GPU (`CUDA_VISIBLE_DEVICES`), автоперезапуск при
  падении с экспоненциальной задержкой.
- **Логи** — сбор/ротация логов, маскирование секретов, экспорт диагностического ZIP.
- **Настройки** — автозапуск при входе в Windows (через Планировщик задач), защита от перегрева
  (пороги предупреждения/критики), язык интерфейса.
- **Профили** — несколько независимых профилей (адрес/ноды/GPU-назначения), переключение и
  быстрый просмотр без входа в профиль.
- **Мастер первого запуска** — проверка системы, ввод адреса с валидацией, создание профиля.
- **Локализация** — ru/en/es/it/fr/uk, переключается на лету.
- **Автообновление бинарников** — проверка релизов `keryx-node`/`keryx-miner` на GitHub, загрузка
  и замена с бэкапом старого файла, ничего не применяется без явного клика пользователя.
- Инсталлятор (Inno Setup) и портативная ZIP-сборка.

## Структура

```
docs/                        - исследование Keryx, архитектура, сборка, релиз, безопасность, гайды
src/KeryxNodeManager.Core/    - домен: GPU, тиры, CLI-builder, supervisor, конфиг, RPC-клиент,
                                загрузка data dir, разгон (интерфейс + mock)
src/KeryxNodeManager.App/     - WPF-приложение (MVVM, DI, трей, реальный NVAPI-разгон)
tests/KeryxNodeManager.Core.Tests/ - xUnit, 170 тестов (Core-слой; App/WPF не покрыт юнит-тестами,
                                см. PROJECT_STATUS.md)
installer/                   - Inno Setup script
scripts/                     - PowerShell-скрипты сборки/упаковки
artifacts/                   - собранные .exe/.zip (после сборки, не в git)
```

## Быстрый старт (для разработчика)

Подробности — в `docs/BUILD.md`. Коротко:

```powershell
dotnet restore
dotnet test tests\KeryxNodeManager.Core.Tests\KeryxNodeManager.Core.Tests.csproj -c Release
dotnet run --project src\KeryxNodeManager.App -- --mock
```

`--mock` запускает интерфейс с виртуальными видеокартами и без реальных Keryx-бинарников/NVAPI —
удобно для просмотра UI без риска для железа.

## Известные ограничения

Полный, честный и постоянно обновляемый список того, что сделано / в работе / чего не хватает —
в `PROJECT_STATUS.md` (включая реальные найденные и исправленные баги, и что именно было
проверено вживую на реальной машине, а что нет). Коротко на сейчас:

- Разгон видеокарт зависит от недокументированного NVAPI — на GPU без выставленного
  clock-boost/cooler (например compute-only карты вроде NVIDIA CMP) приложение честно показывает
  «разгон недоступен» с причиной вместо ошибки.
- Торрент-загрузка data dir (`MonoTorrent`) проверена только на уровне логики диспетчеризации
  (HTTP vs torrent по URL) — полная загрузка через реальный `.torrent` под нагрузкой не
  прогонялась.
- Реальное применение изменений частоты/кулера (кнопка «Применить» на странице Видеокарты)
  сознательно не тестировалось без присутствия пользователя — это единственное действие в
  приложении, которое может повлиять на стабильность/срок службы железа.

## Документация

- `docs/KERYX_RESEARCH.md` — проверенные факты о keryx-node/keryx-miner (CLI, tiers, VRAM, RPC API).
- `docs/ARCHITECTURE.md` — почему WPF, почему native-Windows backend вместо WSL2 по умолчанию.
- `docs/BUILD.md`, `docs/RELEASE.md` — сборка и релиз.
- `docs/SECURITY.md` — принципы безопасности (без shell-конкатенации, без seed-фраз и т.д.).
- `docs/USER_GUIDE_RU.md`, `docs/TROUBLESHOOTING_RU.md` — для конечного пользователя.
- `docs/RECOVERY.md` — как продолжить разработку после потери контекста/сбоя окружения.
- `PROJECT_STATUS.md` — текущий статус, что сделано/в работе/дальше, известные ограничения,
  журнал всех итераций разработки (что именно проверялось вживую, какие баги были найдены).
- `CHANGELOG.md` — покрывает только самую первую версию (0.1.0); `PROJECT_STATUS.md` — более
  полный и актуальный журнал изменений.
